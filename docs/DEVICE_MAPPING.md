# DEVICE_ERROR 设备与故障码映射（3.6）

依据本次提供的协议截图以及主工程 PublishState 的现有编码方式。截图规定“故障设备 ID：char；设备故障码：Int16，原值传送”。当前主工程实际成员类型为 int8_t 和 int16_t。

## State 中的输入

主工程使用以下表达式构造错误描述：

```cpp
device_error.errorType = "DEVICE_ERROR";
device_error.errorDescription =
    std::to_string(g_id_error_device_) + " -> " +
    std::to_string(g_error_code_device_);
```

0xFFFF 存在 int16_t 中为 -1，因此驱动器1掉线实际可收到 `9 -> -1`。3.2 只接受非负十进制，导致这条错误落入 device/unknown；3.3 恢复原始 16 位数值后查询映射表。

`9 -> -1`、`9 -> 65535`、`9 -> 0xFFFF` 全部归一为 `fault:device/9/65535`，保持同一播报身份，避免因输入表示变化而打断。ID 同样兼容 int8_t 的负数形式；例如 -1 表示原始 ID 255。

设备 ID 为 0 表示无故障设备，不生成故障候选。非零 ID 下未定义的故障码（包括 0）仍作为原始码处理，不擅自认定无故障。

## 故障码表

| 适用设备 | 原始故障码 | 内置播报 |
| --- | --- | --- |
| 驱动器1～8，即 ID 9～16 | 0xFFFF，即 65535 或有符号 -1 | 驱动器N掉线，复位无法清除，需断电重启。 |
| 已知设备 | 其他码 | 设备名＋故障，故障码X。 |
| 未知设备 ID | 任意未映射码 | 车体设备故障，设备编号X，故障码Y。 |

本次截图只明确了驱动器掉线码。其他驱动器及扩展板、陀螺仪、电池等具体错误含义未给出，继续保留原始数值。设备故障码不按位图拆分，也不把驱动器专有码应用到非驱动器。

维护位置为 src/AnnouncementTable.cpp 的 devices 与 device_codes。添加单个设备专有码时，将 first_id 和 last_id 都设成该设备 ID；共用码可使用 ID 范围，按表的先后顺序匹配。

## JSON 资源

故障稳定键仍为 `fault:device/设备ID/归一化后的十进制故障码`。3.6新增设备级资源 `fault:device/ID/*`，只控制资源匹配，不改故障身份。例：

```json
{
  "fault:device/9/*": {
    "file": "../audio/069.mp3"
  }
}
```

驱动器1任意有效故障码均可播放069“驱动器一异常或掉线”；没有配置text，文件不可用时继续使用具体错误的内置TTS，65535仍是“驱动器1掉线，复位无法清除，需断电重启。”。

匹配次序：`fault:device/9/65535` → `fault:device/9/*` → `fault`。以后增加专用录音，只添加精确条目。精确条目存在且file为空，表示该故障直接使用TTS；文件不可用同样回退该条目的TTS，不再转播设备通用文件。原有精确键配置完全兼容。

默认已绑定ID1～5、7～14；ID6预留、驱动器7/8（ID15/16）没有录音，继续TTS。未知但合法ID使用含编号和码值的TTS；描述无法解析时使用051“AGV本体故障”。录音编号061～074仅为素材编号，绝不当作设备故障码。详表见 FAULT_MAPPING.md。

file相对于JSON所在目录解析。编号文件放在audio目录；构建demo自动复制录音及配置。text可以省略，使用映射表中可包含具体设备码的文案。

## 常规故障补充

| 位 | 数值 | 资源键 | 含义 |
| --- | --- | --- | --- |
| bit2 | 4 | fault:common/2 | IPC 故障汇总，播报工控机故障；具体 IPC 错误在本类内更优先 |
| bit3 | 8 | fault:common/3 | 举升限位异常 |
| bit5 | 32 | fault:common/5 | 工控机参数匹配异常 |
| bit6 | 64 | fault:common/6 | 舵轮差速转向超时 |

bit6 沿用此前未定义位的 Other/order=106 位置，不新增截图中未规定的优先级关系。其余场景、去重、重复和抢占机制不变。
